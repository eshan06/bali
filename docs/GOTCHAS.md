# Gotchas — live traps of this repo's environment and process

Known traps that sessions kept rediscovering the hard way. Skim this before
touching infra, CI, git plumbing, or the dev environment.

**Rules for this file (they are what keep it useful):**

- **Live traps only, current truth only.** The PR that fixes a trap deletes
  its entry. History belongs in git, not here.
- **One entry per trap, a few lines each.** What bites, and what to do.
- **A note is the last resort.** A critical or recurring finding first becomes
  something that can't be skimmed past — a regression test, a CI check, or a
  CLAUDE.md rule. Only a trap that fits none of those (environment quirks,
  process mechanics) belongs here.
- **Product risk is not a gotcha.** Known product issues live in
  `docs/ISSUES.md`; this file is environment and process only.

## Git / GitHub

- **Cloud sessions: open and edit PRs with the GitHub MCP, not `gh`.**
  `gh pr create` fails (GraphQL is blocked here), and a PR body written
  through `gh api` gets the "Generated by Claude Code" footer even on a
  PATCH. Only the MCP `update_pull_request` writes a clean body — the one
  CLAUDE.md's no-attribution rule and its check need.
- **Remote session branches auto-delete when their PR merges.** A later push
  to the same branch name then fails with `stale info` (force-with-lease) or
  surprises with `[new branch]`. Run `git fetch --prune origin` before
  re-pushing a session branch; `stale info` means your tracking ref is stale,
  not that someone else pushed.
- **Auto-merge can race your push.** If auto-merge fires while you're
  amending, your push lands on a deleted branch and recreates it with
  already-merged history. Rebuild: reset the branch onto the new `main`,
  cherry-pick only your new commit, `push --force-with-lease`, open a fresh
  PR.
- **Editing `.github/workflows/claude-review.yml` or `claude.yml` trips the
  action's tamper protection** — the guard covers the Claude workflow files
  themselves, not all workflows (observed: PRs editing `ci.yml`,
  `plan-check.yml`, and `dependabot-automerge.yml` reviewed normally). That
  PR's own Claude Review check is red by design and cannot be fixed by
  pushing; merging it takes the owner's one-time ruleset toggle (remove the
  check from `protect-main`, merge, re-add it). The toggle is repo-wide and
  owner-only: while the check is removed, any other green PR would merge
  unreviewed — disarm other PRs' auto-merge first, and re-add the check
  immediately after. Sessions never request the toggle as a routine remedy
  for a red check; it is an owner decision, proposed only for a
  workflow-file PR where no other path exists (its own red review is the
  designed behavior, not a bug to fix).
- **GitHub silently disables a PR's auto-merge when a required check fails.**
  After driving the check green, re-enable auto-merge — a green PR otherwise
  just sits there.
- **A draft's failed Claude Review stays in the API after the review
  passes.** A draft's run fails by design ("Draft: …"), and the head commit's
  check runs and GraphQL's `statusCheckRollup` (state FAILURE) keep it after
  the ready review passes. The merge box and `gh pr checks` read only the
  newest run: judge a PR by `mergeStateStatus` or `gh pr checks`, never the
  rollup's state. A push clears it.
- **Dependabot-triggered workflow runs read the _Dependabot_ secrets store,
  not Actions secrets.** A secret needed in those runs must exist in both
  stores (`CLAUDE_CODE_OAUTH_TOKEN` does).

## The owner's Mac

- **`npm run demo` runs against dev there, not in memory.** The shell profile
  exports `DEMO_API_URL` and the demo accounts, and the demo picks remote mode
  whenever `DEMO_API_URL` is set — so the run exercises the deployed `main`,
  not your branch, and its silence step waits on dev's sweep. For the in-memory
  run CLAUDE.md's verify step asks for: `env -u DEMO_API_URL npm run demo`.
- **A worktree under `.claude/worktrees/` starts with no `node_modules`.** Node
  then resolves `@bali/shared` and `@bali/db` up the tree to the main
  checkout's packages — another branch — so typecheck, lint and vitest compile
  your branch against the wrong sources ("has no exported member" for a type
  you just added). Run `npm ci` in the worktree before the first check.
- **The Simulator cannot read the checkout in place.** The repo lives under
  `~/Downloads`, which macOS's privacy protection keeps from the Simulator: a
  test hosted there that reads a repo file through `#filePath` fails with
  `EPERM` (Cocoa error 257) — here only; CI's runner passes. So BaliOutbox's
  contract tests (`contracts/`) and `BellTests.monitorsCalls` fail on this
  Mac's Simulator: run the packages with `swift test` here. A test of the
  app's that needs a file carries it as a `BaliTests` resource
  (`ios/project.yml`, as `bali-tokens.json` is).

## The Windows PC

The conductor's machine since 2026-10-14 (`docs/DECISIONS.md`), replaced by a new PC on 2026-10-21;
the clone is `C:\Users\Eshan Shah\Downloads\github\bali`. Its path has a space: always quote it.

- **Node 22 runs only in Git Bash.** fnm (from winget) installs it and `~/.bashrc` loads it, without
  `--use-on-cd`; PowerShell and cmd find the system's own Node, which lacks the `script-shell`
  setting below (and a Node 24 there is refused by the repo's `engine-strict`). Run npm, git and the
  repo's scripts in Git Bash, which is Claude Code's Bash tool.
- **npm runs scripts in Git Bash by a setting outside the repo.** The scripts use `NODE_ENV=…`
  prefixes and quoted globs, which cmd can't run, so `script-shell` names Git Bash in Node 22's own
  global npmrc. fnm installing a newer 22.x starts without it: set it again there.
- **Git Bash rewrites a `<rev>:<path>` whose path starts with a dot.** `git show
  origin/main:.github/workflows/claude-review.yml` (santa-loop's Step 1) reaches git as
  `origin\main;.github\workflows\claude-review.yml`, "ambiguous argument", while
  `origin/main:docs/PLAN.md` passes. Prefix such a command with `MSYS_NO_PATHCONV=1`.
- **`cd` in the Bash tool can fail if fnm's `--use-on-cd` is on.** It turns `cd` into its own
  function, which can stop with "We can't find the necessary environment variables to replace the
  Node version". Keep it out of `~/.bashrc`; otherwise use `git -C <path>`, absolute paths or `builtin cd`.
- **Line endings.** Git for Windows checks files out with CRLF by default and the repo is LF, so
  the clone sets `core.autocrlf=input` (its worktrees share it). A clone made before the setting
  keeps CRLF files on disk though `git status` is clean: check `git ls-files --eol`, and re-checkout
  (`git rm -rq --cached . && git reset --hard`) when it shows `w/crlf`.
- **Headless Chrome lays a page out 500 px wide at least.** `--window-size=390,…` renders at 500 and
  crops the shot to 390, a layout no phone has, with no error. For a phone-width shot, emulate the
  width over DevTools: start it with `--remote-debugging-port`, then `Emulation.setDeviceMetricsOverride`
  and `Page.captureScreenshot` (Node 22's built-in `WebSocket` is enough).
- **Publishing to a canvas from the scratchpad takes the folder's long path.** The session names its
  scratchpad in Windows' short form (`C:\Users\ESHANS~1\…`), and a publish from that path fails as
  "blocked by a Read permission rule"; the same folder as `C:\Users\Eshan Shah\…` publishes. A
  publish refused with "you haven't viewed the latest version" wants a read of the artifact itself
  (only its `url`), not only of its files, before it goes.

## Android's SDK on Windows

The PC whose clone is `C:\dev\bali` holds Android's SDK and its test emulators
(`docs/PLAN-ANDROID.md`, Who builds what).

- **The SDK's `.bat` tools split a package name at its semicolons.** From Git Bash,
  `sdkmanager.bat "system-images;android-36;google_apis;x86_64"` reaches cmd as four names
  ("Package system-images not found") and installs nothing, yet exits 0. `sdkmanager` now wraps
  the Android CLI: run `cmdline-tools/latest/bin/android.exe sdk install
  system-images/android-36/google_apis/x86_64`, with slashes. Make an AVD through the JBR's `java`
  with `-classpath <cmdline-tools>/lib/avdmanager-classpath.jar com.android.sdklib.tool.AvdManagerCli
  create avd …`, where a quoted argument keeps its semicolons.
- **`android emulator start` never ends behind a pipe.** It returns once the emulator has booted,
  but the emulator keeps the command's output open, so `android emulator start … | tail` waits
  until the emulator stops (the Bash tool's 10 minutes, then the background). Send its output to a
  file, and stop the emulator with `adb -s emulator-5554 emu kill`.
- **An image's folder isn't an installed image.** A download Android Studio left unfinished leaves
  the folder holding only `.installer/`; Android 17's Play Store image
  (`android-37.0/google_apis_playstore_ps16k`) still is one. An image is installed when its folder
  holds `source.properties` and `package.xml`.
- **A reboot can end the emulator instead.** `adb reboot`, or the power menu's Reboot to safe
  mode, often powers the emulator off, or hangs it with adb still listing it and its shell never
  answering. Stop it (`emu kill`; if that hangs too, end `qemu-system-x86_64-headless.exe`) and
  start it again with `--cold`: that is a boot all the same, and a Safe Mode asked for still takes.
  Safe Mode also turns Airplane mode on, and it stays on after
  (`adb shell cmd connectivity airplane-mode disable`).
- **A worktree's worker can't hand adb or bash a script file.** Its isolation check refuses
  `adb shell sh <file>` and `source`, often `bash <file>` and some long `adb shell '…'` strings,
  as text it can't read. Inline a short loop in `adb shell '…'`, and split a long one into plain
  commands. A host-side `for` loop around adb, a command named by a variable (`$A shell …`) and a
  long Python heredoc are refused too: write each adb call out in full, one after another.
- **`uiautomator dump` unbinds Bali's lock service while it runs.** Its UiAutomation suppresses
  accessibility services, so Android unbinds Bali's, still on its list: the Debug readout reads the switch
  starting, not locked, until it binds again. Find a control's place from a dump taken before the step that
  matters, and take the screenshot with `adb exec-out screencap -p` alone.
- **Uninstalling Bali with its service on leaves dead bindings behind.** `adb uninstall` or a reinstall
  while the service is switched on leaves Android's own connections to it, marked `DEAD`, in `dumpsys
  activity services com.bali.bali` until the emulator restarts, and LockServiceTest's
  `aServiceAndroidUnbinds…` reads them as the service still there. Switch the service off first (`settings
  delete secure enabled_accessibility_services`); a cold boot clears them.
- **Git Bash rewrites a device path handed to adb.** `adb shell uiautomator dump /sdcard/ui.xml`
  and `adb exec-out cat /sdcard/ui.xml` reach adb as `C:/Program Files/Git/sdcard/ui.xml`, so the
  dump lands nowhere and the read fails, or reads an old file. Prefix such a command with
  `MSYS_NO_PATHCONV=1`.

## Cloud sessions / dev environment

- **A sign-up on dev's hosted page fails.** Dev's Cognito pool (`us-east-1_YTloqilwT`) verifies
  no attribute, so its Sign up makes the account unconfirmed and lands on Cognito's "An error was
  encountered with the requested page." Use the existing demo accounts (`$DEMO_USER_TEACHER` and
  the students the owner's shell exports) until the owner turns on email verification in the
  console; then delete this entry.

- **Dev's demo teacher can turn back into a student.** Provisioned 2026-09-22, the row read
  `role = 'student'` again on 2026-09-26, cause unknown: no code path turns a teacher into a
  student (a first sign-in makes a student row; an invite's redeem, T1b, only ever makes a
  teacher). `npm run dev:teacher` then refuses every command, `class` and
  `block` included — `… signed in as "student" but the demo needs "teacher"` — and prints the SQL
  that fixes it, the teacher's id filled in (README, "Running it against a deployed API", step 3).
  The owner pastes it into Railway's query tab on dev's Postgres; a session cannot reach that
  database.
- **Egress is allowlisted by the cloud environment's network policy.** Any
  new external host a session needs (an API, a registry) must first be added
  by the owner in the environment settings. A proxy 403 is an org policy
  denial to report to the owner, never to route around.
- **The environment's UI "setup script" field must stay empty.** Dependency
  install belongs to the repo's SessionStart hook; the why lives in
  `.claude/hooks/session-start.sh`'s header comment (the source of truth for
  this trap — this entry exists only because the field is configured outside
  the repo, on claude.ai).
- **A cloud session's outbound address rotates.** Its requests leave from many addresses (seen:
  160.79.106.x, 9+ addresses in 18 requests), so one session can't exhaust a per-address budget
  on dev (L1's). Test per-address limits in process (`apps/api/test/rate-limits.test.ts`) or in
  CI, never against dev from a session.
- **Santa's reviewers run in the worker's own turn, in the foreground, and the worker waits for
  them.** A reviewer started as a background Agent is lost or unheard once the worker's turn ends
  (D2b's worker lost both that way; foreground `claude -p` re-runs worked). Foreground `claude -p`,
  or Agent calls not in the background; never remote sessions.
- **Sessions on dev really expire.** The API sweeps every minute by itself
  (session expiry + silence detection), and a Railway cron POSTs
  `/internal/sweep` as its backup. Timing-sensitive steps against dev must
  account for it. `/internal/sessions/expire` is a live alias of the same
  handler — nothing 404s.
